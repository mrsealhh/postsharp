# PostSharp 产品化路线（v1.11.13 基线）

> 基线版本：**v1.11.13**（2026-11-02）
> 基线能力：桌面三平台（Windows / Linux / macOS arm64）+ Windows NativeAOT + CLI 三平台 + Linux 无头包；MCP 89 个工具；320 个测试通过
> 本文件是**当前有效**的产品化路线。2026-10-31 的历史 TODO、P0 详案和交接清单已归档到 [`docs/archive/product-todos-v1.10.24.md`](archive/product-todos-v1.10.24.md)。
> 文档性质：路线与验收标准，不是已承诺的排期；P0 先做，P1/P2 由产品负责人确认后启动。

## 1. 我们现在在哪

### 1.1 已交付（摘要）

| 方向 | 现状 |
| --- | --- |
| 调试 | HTTP / GraphQL / SSE / WebSocket / Socket.IO / TCP / SOAP / gRPC 一元；Cookie、授权、上传、代理级重定向开关 |
| 数据 | 本地 SQLite 兜底；PostgreSQL / MySQL / SQL Server / MongoDB 默认插件；ClickHouse / Doris / StarRocks 可选插件 |
| 自动化 | 套件 DAG、分支/汇合、断言、重试、映射、并行、预检、运行历史、失败重跑、从节点继续 |
| 流水线 | YAML/JSON：`${步骤别名.字段}`、数据行、循环、并发组、重试、JSONPath 断言、JUnit/JSON/Markdown 报告 |
| AI / MCP | 89 个工具、意图工具、job 幂等、资源化报告、token 与只读/发送/修改/管理四类权限 |
| CI | 无头模式、Docker、CLI、Linux 一体化无头包、可复用 `postsharp-pipeline` workflow |
| 发布 | 每版自动构建 8 类资产 + SHA256；桌面自动更新（带发行说明卡片）；winget / Scoop / Homebrew 清单模板 |

完整历史见归档文件；最近的版本记录见 [`CHANGELOG.md`](../CHANGELOG.md)。

### 1.2 距离“产品化”还差什么

产品化不是再加协议，而是让陌生人能**装得上、用得顺、敢依赖、出问题能定位、团队愿意付费**。当前五个缺口：

1. **分发可信**：Windows 无 Authenticode、macOS 无签名/公证、无 MSIX/MSI/dmg 安装器；包管理器只有模板，未提交上游索引。
2. **上手成本**：文档散在 README 与 `docs/`，缺面向新人的 5 分钟教程、场景模板和可复制的最小 CI 示例仓库。
3. **可依赖**：性能与稳定性没有 CI 门禁；崩溃只能靠日志，没有一键诊断包；长时间运行与大数据量未压测。
4. **闭环一致性**：套件编辑器还没有数据驱动/循环；工作区仍是 SQLite 单文档，Git diff/评审困难；报告分散在各次运行里，没有汇总视图。
5. **可运营 / 可商业化**：没有版本节奏承诺、反馈入口、使用指标（默认关闭）、团队授权与企业功能。

## 2. 什么叫“产品化”

### 2.1 五条验收线

| 验收线 | 判定标准（陌生人视角） |
| --- | --- |
| 装得上 | 官网/GitHub 一眼找到对应平台包；安装/解压后 1 分钟内能发出第一个请求；升级不会丢数据 |
| 用得顺 | 5 分钟内完成“导入接口 → 改参数 → 断言 → 存成流水线 → 命令行跑通” |
| 敢依赖 | 版本语义清晰；CI 可固定版本；失败有退出码、报告和可复现输入；升级可回滚 |
| 能定位 | 出问题能一键导出诊断包（版本、设置、插件、日志尾部，去机密）；错误文案给出下一步 |
| 愿付费 | 团队协作、审计导出、企业部署/SSO 等能力有明确边界，本地离线仍可用 |

### 2.2 指标

**北极星**：每周“跑过至少一次自动化（套件或流水线）”的工作区数。

| 类别 | 指标 | 目标 |
| --- | --- | --- |
| 上手 | 安装 → 首次成功请求 | 中位数 < 5 分钟 |
| 自动化 | 安装 → 首次 CI 运行 | < 30 分钟（含模板） |
| 依赖 | CI 连续 30 天成功率 | ≥ 99%（非被测服务原因） |
| 质量 | 崩溃自由会话比例 | ≥ 99.5% |
| 性能 | 冷启动 / 空闲内存 / Windows 包 | < 1.5s / < 150MB / ≤ 75MB |
| 支持 | 问题首次响应 | 工作日 < 1 天（社区）/ 4 小时（商业） |

默认只做本地统计；任何上报必须显式同意、可关闭、可删除，且不采集请求内容与令牌。

## 3. 下一阶段路线

### 3.1 本轮已定（v1.11.x，约 2–3 周）

按顺序推进，完成后即可对外称“可产品化试用”：

| ID | 事项 | 验收 | 规模 |
| --- | --- | --- | --- |
| N-01 | 场景模板库：8–10 个 `.postsharp-scenario.json`（登录链路、分页拉取、并发检查、数据矩阵、契约冒烟等）+ 一键导入/导出 | 新用户从模板到跑通 < 10 分钟；模板不含真实令牌 | M |
| N-02 | 文档站单页：安装、5 分钟上手、流水线、CI、故障排查；README 只保留入口 | 三条主路径各有可复制命令，截图来自演示数据 | M |
| N-03 | 包管理器上游：winget / Scoop / Homebrew 提交索引 | `winget install`、`scoop install`、`brew install` 至少一个渠道可用 | M |
| N-04 | 诊断包：版本、系统、设置（去机密）、插件清单、日志尾部、最近失败运行 | 一键导出 ZIP；MCP/CLI 也能触发；不含令牌与请求体 | M |
| N-05 | 性能/稳定性门禁进 CI：启动时间、空闲内存、包体、无头就绪时间 | 超阈值 CI 失败；基线写入文档 | S/M |
| N-06 | 发布检查单自动化：资产齐全、SHA256、AOT 冒烟、CLI 版本、无头包结构 | 发布 workflow 缺项即失败 | S |

> 签名与安装器（P0-01）依赖证书采购，先做“可签名”的流水线开关与文档，证书到位后当天可启用。

## 5. 完成定义（DoD）

功能、文档、发布三类改动统一要求：

- [ ] 成功、失败、取消、恢复四条路径都有明确反馈；错误文案可直接给用户看。
- [ ] `dotnet build` 0 警告 0 错误；新增测试覆盖成功/失败/边界；`csharpier check .` 通过。
- [ ] 涉及 MCP 的新增能力同步更新工具说明、权限分类和 `tools/list` 计数。
- [ ] 涉及 UI 的改动更新 `docs/` 截图；README「验证记录」补一行。
- [ ] 不把工作区、审计、令牌、连接串、演示数据写入仓库或发布包。
- [ ] 发布资产齐全且有 SHA256；AOT、CLI、无头包各自冒烟通过。
- [ ] 不升级 Avalonia / TKCode.Arc / SDK，除非单独走版本升级决策。

## 6. 风险与不做清单

**风险**

- 签名证书与 Apple 公证依赖外部采购和账号，排期不由仓库控制；先做开关与文档。
- 包管理器上游审核周期不可控；至少保证一个渠道可用。
- 企业能力（SSO/RBAC）与“本地优先”冲突，需先定边界：本地离线必须完整可用。
- 协议深化会推高包体，必须模块化，不能进主热路径。

**暂不做**

- 不做强制云同步、账号体系、计费墙、移动端。
- 不做“每个 UI 动作对应一个 MCP 工具”；MCP 以意图和工作流为单位。
- 不做没有真实样例和验收标准的协议。
- 不做远程代码执行型插件市场。
