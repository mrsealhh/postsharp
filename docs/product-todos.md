# PostSharp 后续产品化 TODO 与开发交接

> 基线版本：v1.10.24（2026-10-29）
> 基线形态：Windows x64 / Linux x64 / macOS arm64 三类 ZIP（含按平台裁剪的存储插件），CLI 独立发布；.NET 10，Avalonia 12.1.4，TKCode.Arc 0.3.2-preview.1
> 基线测试：232 个 xUnit 测试，`csharpier check .` 通过
> 线上版本：https://github.com/mrsealhh/postsharp/releases/tag/v1.10.24
> 平台策略：**共享核心按跨平台设计；Windows 专属能力隔离为可关闭 feature；Linux/macOS 实施统一列入 P2-02，后续排期。**
> 文档性质：产品待办与技术交接，不是已承诺的版本计划；P0 先做，P1/P2 由产品负责人确认后再排期。

## 1. 产品定位

### 1.1 目标用户

- 需要频繁调试 HTTP / OpenAPI 接口的后端、前端、测试和 AI 工具使用者。
- 希望保留本地数据、可控审计和可回放回归，而不是把所有请求交给云端 SaaS 的团队。
- 需要通过 MCP 让 AI 客户端触发真实请求，但要求有人可接管的桌面工作台。

### 1.2 核心闭环

```text
界面手动调试 / 导入接口定义
        ↓
环境变量 + 授权 + 请求组合
        ↓
发送请求 / SSE 流式响应 / MCP 触发
        ↓
审计留痕 + 历史回收站
        ↓
套件回归 + 失败定位 + 结果导出
```

### 1.3 产品原则

1. **本地优先**：默认不依赖云服务；远程存储和团队能力必须可关闭、可回退。
2. **数据可恢复**：删除走回收站，写盘失败可见，升级不得静默丢数据。
3. **密钥最小暴露**：界面、日志、审计、MCP、截图和发布包都不能泄露凭据。
4. **AI 可接管**：MCP 调用必须可审计、可取消、可复现，不能绕过人工确认的破坏性操作。
5. **离线可用**：网络、数据库或更新服务不可用时，核心调试能力仍然可用。
6. **发布可信**：安装包、更新包、插件和发布资产必须可校验来源与完整性。
7. **跨平台设计优先、跨平台发布后续实施**：新增共享代码不直接绑定 Windows API；Windows 专属能力单独 feature；Linux/macOS 正式支持按 P2-02 择期启动，不阻塞当前 Windows 版本。
8. **轻量模块化**：核心保持小、启动快、离线可用；协议和扩展按模块/包加载，不把每个新协议都塞进主热路径。
9. **MCP 优先，不是附属**：MCP 是 AI 的第一入口；原子工具保底，意图工具提效，长任务统一 job，大内容走资源。
10. **场景闭环优先于协议数量**：优先做“调试 → 回归 → CI → 报告”的完整链路，再按真实需求补协议。
11. **本地可信**：默认不上传请求、不强制账号；审计、机密打码、MCP token 和发布校验属于产品能力，不是可选项。

### 1.4 产品指标建议

先本地统计、默认不上传；做产品分析时必须另行获得用户同意。建议跟踪：

**轻量与性能**
- 冷启动时间（目标 < 1.5 秒）、空闲内存（目标 < 150 MB）、Windows 自包含包体积（目标 ≤ 75 MB）。
- 1 万条历史/审计记录下的启动时间、内存和列表滚动帧率。
- 大响应渲染、SSE 长会话和 100 个套件节点下的 UI 卡顿次数。

**MCP 与 AI**
- 首次安装到 MCP 首次成功调用的耗时（目标 < 5 分钟）。
- MCP 工具调用成功率、失败原因分布、取消率、p95 延迟。
- 意图工具占比（`verify_endpoint` / `generate_suite` / `diff_runs` 等）与平均工具调用次数。
- 大内容走资源的比例、tool text 超限次数、并发客户端数。

**回归与团队**
- 套件通过率、失败步骤定位耗时、无人值守运行成功率。
- CI 运行次数、回归失败发现数、报告导出次数。
- 安装 → 首次成功请求的转化率、周活跃工作区、每工作区套件数。

**稳定性**
- 远程存储测试连接/写入成功率、冲突率、回退本地次数。
- 崩溃自由会话比例、更新成功率、回滚次数。

### 1.5 暂不作为近期目标

- 不追求 100% 复刻 Postman 的脚本、测试和全部协议。
- 不在没有明确需求前引入强制云同步、账号体系、计费和移动端。
- 不为了“功能多”牺牲本地启动速度、内存和离线可用性。
- 不承诺插件热卸载；进程内插件隔离是当前明确的技术边界。
- 不追求“每个 UI 动作都变成一个 MCP 工具”；MCP 以意图和可复用工作流为单位。
- 不用协议数量作为版本目标；没有真实样例和验收标准的协议不排期。

### 1.6 平台实施边界

**当前正式支持**：Windows 10/11 x64。Windows ARM64 尚未验证，Linux / macOS 尚未发布。

**后续实施**：Linux / macOS 的完整方案统一放入 P2-02（见 6.2 节），由产品负责人择期启动，不纳入当前 Windows 版本的交付承诺。

从本文件生效后，新增和重构代码遵守以下约束：

- [ ] 共享核心（ViewModel、服务、模型、导入导出、套件）不新增直接 Win32、DPAPI、WebView2、PowerShell 依赖。
- [ ] 平台能力通过接口注入；后续按 `ISecretProtector`、`IEmbeddedBrowser`、`IUpdateInstaller`、`IPlatformTheme` 等边界收敛。
- [ ] Windows 专属能力无法跨平台实现时，单独放到 Windows 平台模块/feature，并在其他平台提供安全降级或无操作实现。
- [ ] Windows 专属 feature 使用独立分支和 PR，例如 `feature/win-dwm-titlebar`，不得把 Windows 包引用、P/Invoke 或注册表访问带进共享核心。
- [ ] 任何功能 PR 必须说明平台影响；涉及平台边界变更时，至少完成跨平台编译检查。
- [ ] 现有 Windows 专属实现（DPAPI、PowerShell 更新器、DWM 标题栏）保持现状，不在其他 P0/P1 任务中强行重构；在 P2-02 启动时统一迁移。
- [ ] 已列入 P0/P1 的 Windows 安全与发布交付项（DPAPI 机密落盘、签名安装器、Windows CI）按当前 Windows 版本完成，不因 P2-02 延后；P2-02 启动后再抽象为平台接口。

### 1.7 产品主线（v1.10.21 之后）

**定位**：AI 可驱动的本地接口调试与回归工作台，而不是“另一个 Postman”。

四个差异点：

1. **本地优先**：请求不上传、不强制账号、机密打码、审计可查。
2. **MCP 原生**：AI 能完整驱动调试、套件、回归和报告，而不是只做“生成请求”。
3. **协议够用**：HTTP / GraphQL / SSE 为核心；WebSocket / Socket.IO / TCP / SOAP / gRPC 为模块；MQTT 按需独立。
4. **闭环**：单次调试 → 套件 → CI → 报告 → 复盘，结果可回归、可交接。

三条主线，按此顺序投入：

| 主线 | 目标 | 关键结果 |
| --- | --- | --- |
| A. 轻量核心 | 启动快、包体小、安装省心、模块可选 | 冷启动 < 1.5s、空闲内存 < 150MB、Windows 包 ≤ 75MB、便携/包管理器可装 |
| B. MCP 全流程 | AI 用更少调用完成完整意图 | 会话/长任务 job、意图工具、资源化大内容、token/权限、结构化错误 |
| C. 场景闭环 | 调试到 CI 的完整链路 | 录制 → 回放 → 生成套件 → CI 报告 → 运行 diff |

## 2. 当前基线与技术现状

### 2.1 已具备能力

- 请求编辑：参数、请求头、Cookie 管理、JSON/XML/Text/GraphQL/Multipart、上传、超时、请求级重定向开关、cURL 预览；协议支持 HTTP / WebSocket / Socket.IO / TCP（单条消息收发）/ SOAP 1.1/1.2 / gRPC 一元调用（服务端反射 + 动态 protobuf JSON）。
- 响应处理：JSON 树、原文、响应头、AI SSE 聚合、大响应折叠、搜索和复制。
- 授权：Bearer、Basic、API Key、OAuth 2.0 授权码 + PKCE / 客户端凭据、集合级继承、请求级覆盖。
- 导入导出：OpenAPI / Swagger、Postman、HAR、cURL、PowerShell、Insomnia V4、Hoppscotch、Postman Environment；集合右键可直接导出 Postman Collection v2.1。
- OpenAPI：离线接口文档、URL 同步、外部 `$ref`、多服务器、安全方案占位、调用代码导出。
- 存储：本地 SQLite 兜底；远程 PostgreSQL / MySQL / SQL Server / MongoDB 默认插件；ClickHouse / Doris / StarRocks 可选插件；连接失败暂停远程回写。
- 自动化：集合/接口混合编排、纯画布工作流、依赖 DAG、条件分支与 All/Any 汇合、断言、重试、输入映射、最大并行、定时运行、保存/运行前预检、最近 20 次运行历史、失败重跑与从节点继续，以及运行中节点/连线状态。
- AI 接入：本地 MCP Streamable HTTP、工具调用、审计、历史、机密遮罩。
- 界面：主题、界面缩放、紧凑布局、标签栏溢出、历史回收站、集合回收站、审计回收站。

### 2.3 当前技术债与风险

| 风险 | 现状 | 影响 |
| --- | --- | --- |
| 主窗口复杂度 | `MainWindowViewModel.cs` 约 5.8k 行，`MainWindow.axaml` 约 5.7k 行，`MainWindow.axaml.cs` 约 1.6k 行 | 修改成本高、回归面大、多人并行容易冲突 |
| 测试结构 | 以服务层单测为主，无 UI 自动化、无真实数据库集成测试 | 界面和真实数据库回归依赖手工 |
| 发布 | 便携 ZIP，未做代码签名、安装器、MSI/MSIX | SmartScreen 提示、企业部署困难、更新可信度不足 |
| 自动更新 | 仅读取最新 Release，固定资产名，PowerShell 辅助替换，SHA256 校验 | 无签名、无灰度、无回滚演练、Windows 专用 |
| 数据模型 | 工作区 JSON、SQLite、远程文档三套存储路径 | 迁移、备份、冲突处理缺少统一版本化和契约 |
| 机密 | 授权令牌/连接串使用 DPAPI；环境变量 `secret` 仍随 workspace JSON 明文落盘 | 本机文件泄露时变量值暴露 |
| 远程存储 | 整份 JSON 文档读写，Revision 由调用方递增，缺少冲突检测 | 多机器/多人同时写入可能静默覆盖 |
| OLAP | ClickHouse 仅完成连接/失败路径；Doris/StarRocks 无实例验证 | 发布支持矩阵存在未验证项 |
| 插件 | 进程内 AssemblyLoadContext 加载，无热卸载、无签名校验 | 插件供应链和稳定性风险 |
| MCP | 仅回环监听；已支持可选本机 token 和只读模式；已提供 5 个意图工具，工具总数 75；无 SSE 通知、无细粒度工具权限 | 本机其他进程可尝试调用（启用 token 后受控）；多客户端能力有限；会话 job、资源化大内容和幂等键仍缺 |
| 协议深度 | SOAP 仅浅层 WSDL；gRPC 仅一元+反射；WS/SIO/TCP 为单轮消息 | 复杂企业协议和常驻会话场景仍需补课，不能对外承诺“全协议” |
| 包体与依赖 | 自包含包约 73 MB；新增 gRPC/Google.Protobuf 依赖 | 继续加协议会推高包体和启动成本，必须模块化 |
| AOT / 裁剪 | 已打通：本地文档与 MCP 结果全部使用 source-generated JSON，`AppSettings` 走显式转换器；Windows 原生 exe 约 63 MB，`scripts/aot-smoke.ps1` 18 项检查通过（启动、当时 70 个 MCP 工具、发送、套件运行、重启后设置持久化），自有代码 0 条 IL 告警；存储插件在 AOT 下自动回退本地 SQLite | 正式发布包仍保持 JIT 自包含；AOT 作为可选通道随版本发布并自更新（只认 `PostSharp-aot-win-x64.zip`），远程存储插件在 AOT 下不可用；新增意图工具后总数 75，冒烟待下一版复跑 |
| 定时套件 | 依赖应用内 DispatcherTimer，应用关闭后不执行 | 不能作为无人值守回归服务 |
| 可观测性 | Serilog 文件日志 + 数据提示条，无崩溃转储/诊断包 | 用户问题定位依赖手工收集 |
| 国际化 | 界面和文案以中文为主 | 海外用户和英文文档扩展受限 |

## 3. 优先级、规模与完成定义

### 3.1 优先级

- **P0：数据安全、发布可信、真实数据库正确性。没有完成前不建议扩大用户规模。**
- **P1：产品可用性和日常效率；决定用户是否愿意长期使用。**
- **P2：平台化、团队化和新协议；有明确客户/场景后再立项。**

规模使用 T 恤码：

- **S**：1–2 天，局部改动。
- **M**：3–5 天，涉及一个子系统。
- **L**：1–2 周，涉及跨模块、迁移或验证环境。
- **XL**：需要产品决策、外部证书/服务或多个迭代。

### 3.2 完成定义（DoD）

每个 TODO 完成时必须同时满足：

- [ ] 功能有明确的成功、失败、取消和恢复路径；错误文案可直接给用户看。
- [ ] 新增/修改代码通过 `dotnet build`，0 警告 0 错误。
- [ ] 新增测试；至少覆盖成功、失败、取消和一个边界条件。
- [ ] `csharpier check .` 通过。
- [ ] 不把本地工作区、审计、Token、连接串、截图演示数据写入仓库或发布包。
- [ ] README「验证记录」补一行；涉及界面的更新 `docs` 演示截图。
- [ ] 不升级 Avalonia / TKCode.Arc / SDK，除非单独走版本升级决策。
- [ ] 发布相关改动在干净 Windows 虚拟机完成安装、升级、回滚和三方校验。

## 4. P0：先做，避免数据事故和发布事故

### P0-01 发布可信链：签名、安装器和可回滚更新

**问题**

当前发布物是未签名的 Windows 便携 ZIP；自动更新下载固定资产，校验 SHA256 后用 PowerShell 替换应用目录。用户会看到 SmartScreen 警告，企业环境难以分发；更新包没有代码签名，更新失败后的回滚也缺少演练。

**范围**

- [ ] 为 `PostSharp.exe` 和随包 DLL 增加 Authenticode 签名；证书类型和采购由产品负责人确认。
- [ ] 生成签名更新清单（版本、通道、最低系统、资产名、SHA256、签名、发布时间）。
- [ ] 支持 `stable` / `beta` 通道；`latest` 只作为默认 stable 的快捷入口。
- [ ] 更新前校验清单签名和包 SHA256；拒绝未知通道、降级和篡改包。
- [ ] 采用原子目录切换：新版本启动自检成功后再清理旧版本；失败自动回滚。
- [ ] 评估 MSIX 或签名 MSI 安装器；保留便携 ZIP 作为企业/绿色版入口。
- [ ] 更新失败、无权限、磁盘不足、网络中断都要有可恢复提示。
- [ ] 增加 `check_updates` 的测试覆盖：最新、无包、校验失败、路径穿越、回滚。

**验收**

- [ ] 干净 Windows 10/11 虚拟机完成安装、启动、升级、回滚。
- [ ] 篡改更新包或清单时拒绝安装且旧版本仍可启动。
- [ ] 普通用户权限下更新失败时给出明确处理路径，不留下半安装目录。
- [ ] 发布页同时提供签名安装包、便携 ZIP、SHA256 和更新说明。

**依赖/风险**：需要代码签名证书；安装器方案涉及分发和权限；不要把证书私钥放进仓库或 CI 明文变量。

**规模**：L/XL。

### P0-02 数据安全底座：备份、恢复、迁移和删除回收

**问题**

工作区、设置、审计和远程文档分散在 JSON / SQLite / 远程库；只有 `.bak` 恢复，没有用户可见的一键备份、完整导出和跨版本迁移；环境删除仍是直接删除。用户在升级、换机或数据库切换时缺少可靠恢复手段。

**范围**

- [ ] 为工作区、设置、审计、套件和回收站定义明确的 `schemaVersion`。
- [ ] 增加「导出完整数据包」和「从数据包恢复」：包含版本、校验和、迁移前备份，不包含明文凭据。
- [ ] 启动时自动创建最近 N 份滚动备份；设置中显示备份位置和最近恢复点。
- [ ] 远程存储切换前强制生成可恢复快照；失败可一键回退本地 SQLite。
- [ ] 环境支持移入回收站、恢复和永久删除，与集合/请求/历史保持一致。
- [ ] 升级脚本/迁移器支持从当前 v1.2.0 数据格式升级；损坏文件要保留原文件并说明下一步。
- [ ] 写盘失败、磁盘满、只读目录、远程不可达时，所有保存入口给出持久可见错误。
- [ ] 数据包导出/恢复增加路径穿越、版本不兼容、部分损坏和中断测试。

**验收**

- [ ] 在干净机器导入数据包后，集合、请求、环境、套件、历史和回收站均可用。
- [ ] 升级中断后可以用最近备份恢复；原损坏文件不被覆盖。
- [ ] 远程切换失败后本地数据完整，远程写入保持关闭。
- [ ] 环境删除可撤销；清空回收站有二次确认。

**依赖/风险**：数据包不能把 DPAPI 密文当成可跨机器凭据；跨机器恢复时需要重新输入授权凭据。

**规模**：L。

### P0-03 机密落盘：环境变量、日志和导出统一脱敏

**问题**

授权令牌、远程连接串和 `secret` 环境变量已经使用本机机密保护；日志、导出文件和诊断包仍可能间接包含敏感 URL、请求头或响应片段，统一脱敏器和敏感值检测尚未完成。

**范围**

- [x] 对 `secret` 环境变量值使用 DPAPI 加密落盘，加载时按当前用户解密。
- [x] 为旧数据做一次性迁移：识别遗留明文，加密后写回，并记录迁移结果。
- [ ] 审计、日志、错误消息、cURL、MCP 返回、数据导出和诊断包统一走脱敏器。
- [ ] 增加敏感值检测：导入 cURL/Postman/HAR 时提示可能包含 Token、Cookie、密码。
- [ ] 设置中提供「清除本机缓存凭据」入口，至少清理授权令牌、本机密钥和更新缓存。
- [ ] 测试覆盖：短密钥、带引号密钥、重复值、URL 编码、大小写变化、导出文件扫描。

**验收**

- [ ] 在 workspace JSON、SQLite、日志、导出包和诊断包中搜索已知密钥均找不到原文。
- [ ] 旧数据迁移后应用可正常启动，授权/变量仍可使用。
- [ ] 关闭 secret 标记时明确提示风险，并要求确认。
- [ ] 发布截图中不出现真实域名、账号、Token 或本地路径。

**规模**：M。

### P0-04 远程存储正确性：真实数据库矩阵、并发和插件契约

**问题**

目前只有本地 SQLite 和部分远程库做过手工验证；Doris/StarRocks 缺少真实实例，ClickHouse 缺少完整写入验证。远程存储以整份 JSON 文档为单位，Revision 没有强制比较，两个客户端可能静默覆盖。插件契约没有兼容性版本和包完整性校验。

**范围**

- [ ] 建立数据库集成测试矩阵：PostgreSQL、MySQL、SQL Server、MongoDB、ClickHouse、Doris、StarRocks。
- [ ] 每个库至少验证：测试连接、首次建表、写入、读取、覆盖写入、重启后读取、断网/超时、权限不足。
- [ ] 使用容器化测试环境（Testcontainers 或等价方案）；不能把“无法连接”当作通过。
- [ ] 为 `WriteAsync` 增加 compare-and-swap 语义或显式冲突结果；Revision 不匹配时拒绝覆盖并提示刷新/合并。
- [ ] 远程文档增加机器/客户端标识、最后写入时间和冲突记录，避免无法定位覆盖者。
- [ ] 提供冲突处理界面：保留本地、采用远程、导出差异，不静默选择。
- [ ] 为插件增加 `ContractVersion`、清单校验和（至少 SHA256）和兼容性检查；不兼容插件只显示为不可用，不阻塞启动。
- [ ] 明确插件升级策略：同名覆盖后重启生效；不做热卸载承诺。
- [ ] 建立“远程不可用只写本地”的故障注入测试。

**验收**

- [ ] 七个 provider 在测试环境有可重复的集成测试记录。
- [ ] 两台客户端同时写同一分类时，第二个客户端收到冲突提示，不丢数据。
- [ ] 插件契约不兼容时应用仍能用 SQLite 启动。
- [ ] 远程写失败后自动暂停回写，并提供恢复/重新测试入口。

**依赖/风险**：Doris/StarRocks/ClickHouse 需要可写实例和建表权限；CI 容器方案需产品负责人批准。

**规模**：XL。

**验收**

- [ ] 诊断包可在另一台机器打开并定位版本/插件/日志问题。
- [ ] 日志和诊断包中不出现测试密钥或完整凭据。

## 10. MCP 覆盖与 CLI 模式

状态：当前 MCP 覆盖集合/请求 CRUD、发送、DAG 套件、后台运行/进度/取消、结构化预检、运行历史、意图工具（验证/生成/报告/对比/解释）、审计/历史/回收站、设置和存储，工具总数 75；**仍不是 UI 功能 1:1 映射**。详细审核见 `C:\Users\Administrator\Desktop\AICoding\postsharp\PostSharp-MCP覆盖审核与CLI计划-2026-10-28.md`。

### 10.1 工具面原则

1. **原子工具保底，意图工具提效**：CRUD/发送保留；新增 `verify_endpoint`、`generate_suite`、`diff_runs`、`explain_failure`、`export_report` 等意图工具。
2. **长任务统一 job**：`start_*` 立即返回 jobId，`get_*_job` 轮询，`cancel_*` 取消；job 结果带稳定 id。
3. **大内容走资源**：工作区快照、OpenAPI/WSDL/proto、运行报告、大响应、审计详情用 `resources`/文件/分页，不塞进 tool text。
4. **错误结构化**：错误码、消息、下一步、可重试标记；不要只返回异常文本。
5. **破坏性操作可控**：删除、发送、覆盖前支持 dry-run 或确认；审计记录客户端、工具、权限和 requestId。
6. **工具 schema 版本化**：新增参数保持向后兼容；废弃工具给替代项和迁移说明。
